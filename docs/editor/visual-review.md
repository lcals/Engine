# 场景效果巡览

通过既有 MCP 预览镜头完成「基线巡览 → 调整源资源 → 相同路线复拍 → 对照分析」。不启动 Gameplay，不创建场景相机节点，不增加编辑器界面。使用 Python 3.11 及以上的标准库，无额外 Python 依赖。

## 固定条件

- 使用相同引擎构建、图形后端、窗口尺寸、场景活动相机投影和路线。保留构建版本及运行日志。
- 先打开目标预览，等待首次资源加载完成，确认 `modified=false`、`reloadPending=false`。关闭统计面板。
- 路线放项目 `settings/`，结果放 `cache/visual-reviews/`；收费资源、截图和项目特有配置遵守项目忽略规则。
- 入口全景、材质近景、明暗交界、室内及高处远景各选一个代表机位。通过不截图的过渡点避开墙体；巡览镜头没有碰撞检测。
- 巡览期间不手动移动镜头、不编辑资源；每次只调整明确的一组参数，再完整复拍。报告中的亮度变化不是视觉质量评分。

路线为 JSON，例如：

```json
{
  "scene": "project/scenes/example.scene",
  "steps_per_second": 12,
  "waypoints": [
    {
      "name": "entrance",
      "position": [0, 2, 10],
      "rotation": [0, 0, 0],
      "travel_seconds": 0,
      "settle_seconds": 1
    },
    {
      "name": "transition",
      "position": [0, 2, 6],
      "rotation": [0, 0, 0],
      "travel_seconds": 3,
      "settle_seconds": 0,
      "capture": false
    },
    {
      "name": "detail",
      "position": [2, 2, 4],
      "rotation": [-10, 20, 0],
      "travel_seconds": 3,
      "settle_seconds": 1
    }
  ]
}
```

`rotation` 是 `[pitch,yaw,roll]` 度。首机位直接定位，之后平滑插值位置并沿各轴最短角度旋转；`travel_seconds` 是到达该点的目标时长。MCP 每一步等待真实回执，慢帧可能延长路线，实际时长和步数写入记录。这是效果巡览，不是帧率或性能基准。

## 采集与对比

先按根 README 启动编辑器及目标场景预览，再执行：

```sh
python3 scripts/preview_visual_review.py \
  --server build/ninja-engine-release/mcp_app \
  --project projects/showcase --runtime-dir build/editor-runtime \
  --route projects/showcase/settings/visual-review.json \
  --output visual-reviews/baseline
```

以上场景路径和机位只是格式示例；按实际项目创建路线文件。工具不启停编辑器，不替换其他活动预览，也不覆盖既有采集目录。默认结束恢复首机位，`--leave-open` 保留末机位；二者都保持预览开启。

修改并保存场景或材质源文件，等自动导入与预览刷新结束，再运行同一命令，输出目录改为 `visual-reviews/tuned`，增加：

```sh
--compare projects/showcase/cache/visual-reviews/baseline/manifest.json
```

每轮产物：

- 原始 PNG：由 bgfx 真实帧回调写入，只有截图回执为 `complete` 才计入成功。
- `manifest.json`：路线、源场景 SHA-256、磁盘活动相机投影、实际机位、渲染参数、分辨率、截图 SHA-256、会话和完成状态。
- `receipts.jsonl`：逐条 MCP 参数及执行回执；核对项目、运行目录、会话及 pending 请求身份。
- `index.html`：自包含报告；有基线时可拖动分界线比较。图片只对 PNG 数据无损重压缩，原始文件不变。

比较要求路线、磁盘相机投影和截图尺寸相同；采集期间场景文件、镜头或渲染参数变化会使本轮失败。未保存内存编辑会明确记录警告，磁盘哈希不能代表这部分状态。该工具不冻结整个资源目录，也不替代模型、纹理及 Shader 版本管理；正式基线应在完成导入、无其他编辑者时采集。失败仍保留已完成的截图和回执，不重发可能已经执行的修改。

首次打开大场景后 GPU 资源准备可能暂时暂停心跳，出现 `No live editor session` 时先确认原编辑器进程和日志；等心跳恢复再用新的输出目录采集，不重复启动实例或重发 pending 修改。

通过 MCP 调整参数后调用 `save_scene`。已加载网格和未覆盖材质保留原 GUID，只导出动态网格及覆盖材质；内容不变的源文件和 meta 不重写。只调灯光或环境时应返回 `meshCount=0`、`materialCount=0`，仅场景变化；重复保存应返回 `resourceCount=0`、`importRequired=false`。保存命令自身不进入撤销栈，参数编辑仍可 `undo` / `redo`，然后再次增量保存。

预览识别自身保存的资源及源文件摘要，自动导入后只提交新目录，保留场景身份、镜头与撤销历史。外部编辑仍走正常热重载和未保存保护；同一场景代次内已保存文件或 meta 被外部修改时，保存明确拒绝覆盖。修改共享源材质或 Shader 前备份相关文件，等待正常导入完成后再采集；不能把外部修改伪装成自保存。

2026-10-31 在神庙实景验证：3585 个节点中，曝光修改、撤销保存、重做保存均仅写场景；1822 个网格引用及 1844 个材质引用复用，3297 个其他源文件与 meta 的大小、时间戳保持不变；无改保存为零写入。自动导入后场景身份及撤销/重做历史保留。受影响的 Debug / Release `editor.scene_persistence` 测试通过，覆盖动态网格、材质覆盖、失败回滚与外部冲突。

## 分析顺序

1. 先检查曝光、颜色空间和天空，避免用额外灯光补偿整体错误。
2. 比较受光与背光石材，平衡三色环境补光和 IBL，防止两份漫反射叠加后失去层次。
3. 检查近景、远景和室内，再调雾密度与颜色；保持空间深度，不靠雾掩盖错误。
4. 检查法线、高光、阴影边缘、遮挡接触、半透明与发光，区分参数问题和缺少渲染能力。
5. 同路线复拍，逐点记录改善、退化和未解决项。不同引擎或不同长宽比的参考图只作定性对照，不宣称逐像素匹配。

2026-10-31 在 macOS Metal、现有 QuickJS Release 编辑器进行了神庙五机位基线及复拍：曝光 `2.4623 → 1.5`、三色环境强度 `1 → 0.45`、平方指数雾密度 `0.007 → 0.0045`；IBL 强度保留 `0.5`。路线通过两个过渡点连接室内和高处全景。结果保存在本地项目缓存，不是跨平台渲染验收；首次画面校准仅调整资源参数，没有 C++ 或依赖变更。


## 三轮调整记录

增量保存修复后，2026-10-31 使用相同 Metal Release 编辑器、路线、投影与 2560×1600 画幅完成三轮，每轮五张真实截图。新增截图共十五张，另保留此前五张基线。每轮检查全部机位后再决定下一轮参数。

| 轮次 | 修改 | 观察 |
| --- | --- | --- |
| 天空与主光 | 项目天空增加具名曝光/饱和度参数，分别使用 0.65 / 1.08；日光强度 3.1 → 2.8 | 天空与云层区分更明显，石阶及山崖亮面略收敛；仍比 URP 参考偏浅 |
| 石材 | 共享建筑材质 `specularHighlights` 1 → 0.65，`normalScale` 1 → 0.8 | 高光和凹凸感温和收敛；全景变化较小，接触阴影问题保留 |
| 局部灯光 | 九盏门灯、室内墙灯、烛灯和补光通过一个 MCP 批次调整，降低强度并适当扩大范围 | 门灯近处黄白热点收敛；室内变化较轻，保持暗部氛围 |

第三轮保存仍只写一个场景资源，自动导入后保留一个批量撤销记录。共享材质源文件修改另保留逐轮备份；当前预览的撤销栈不是跨会话磁盘历史。全局曝光、三色环境、雾及已烘焙 IBL 保持不变，天空显示参数不会自动重烘焙环境照明。

本地报告提供基线及三轮的逐机位切换和滑动对照，以缩放 JPEG 内嵌单文件供手机查看；原 PNG、完成回执和摘要完整保留。该轮是参数调校，未新增 CSM、接触 AO、HDR 最终合成或 Bloom，也不是跨平台或性能验收。

## HDR 接入后的三轮调校

2026-10-31 在已开启 CSM、AO、HDR/Bloom 的神庙基线上再次完成三轮参数调校。每轮通过 MCP 修改、增量保存，再使用相同的七点路线、288 步移动和五个截图机位复拍；看完本轮结果后再进行下一轮。曝光保持 1.5，既有环境光、IBL、AO、天空及材质参数保持不变。

| 轮次 | 调整 | 实景观察 |
| --- | --- | --- |
| 主光亮部 | 方向光强度 2.8 → 2.45 | 岩壁、石阶顶面与屋檐亮部略收敛；未全局降低曝光，室内明暗基本保持 |
| 局部照明与泛光 | 两盏门灯强度 1.8 → 1.6，颜色略向暖白调整；两盏桌边烛灯强度 0.8 → 0.95、范围 2.6 → 3.1；Bloom 强度 0.15 → 0.12、半径 1 → 0.85 | 门柱暖光略收敛，灯芯仍明亮，光晕更集中；桌边照明稍扩展，室内整体变化较轻 |
| 中远景层次 | 平方指数雾密度 0.0045 → 0.0040 | 中景桥梁、墙体的灰蓝遮罩略减，轮廓稍清楚，远山仍保留雾层；近景与室内变化很小 |

三轮均保留，生成十五张新 PNG；连同 HDR 基线共二十张截图。每次保存仅更新一个场景资源，复用 1844 项材质引用、1822 项网格引用，场景仍为 3585 个节点。本轮没有修改 C++、Shader、贴图或模型，沿用已验证的 Release 编辑器，不重跑编译或测试套件。

项目缓存保留三轮前后场景快照、修改记录、MCP 完成回执和采集清单。报告除比较全局渲染参数外，还从快照提取逐灯的强度、范围和颜色；不能因为 `get_render_settings` 不包含逐灯参数，就把主光调整误报为无变化。快照摘要与各轮采集时的源文件摘要匹配；同一路线、投影、机位和图像尺寸经过核对。

本地 `cache/visual-reviews/hdr-polish-review.html` 为四版本、五机位的自包含报告，支持选择任意两个版本滑动比较，图片缩为 1400 像素长边的 JPEG 82 预览，每张只嵌入一次；原始 PNG 保留。三轮属于渐进调色和照明改善，不代表重做构图、材质或解决全部场景问题。仅完成 macOS Metal 实景巡览，未验证其他平台；结束时关闭预览和本轮编辑器进程。
