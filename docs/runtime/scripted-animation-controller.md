# 脚本动画状态机与资源重定向

本文记录 2026-11-04 已确认的动画接口与职责。当前分支已接入 TS 状态机、运行时重定向、基础 IK、骨骼挂点及事件分发；构建与功能证据集中在[测试文档](../testing.md)。完整类图见文末入口。

## 三部分的职责

项目采用**资源、自定义状态机脚本、业务**三部分。业务只传参数；状态机脚本内部判断条件和转换；已有 C++ 动画系统负责执行姿态计算。

| 部分 | 内容 | 不应混入的职责 |
| --- | --- | --- |
| 动画资源 | 独立 Model、Skeleton、Animation；动作别名与角色绑定；后续的骨骼适配、参考姿态、遮罩、IK 骨链、命名挂点和事件数据 | 项目的待机、攻击等状态转换规则 |
| 自定义状态机 TS | 可继承的机器与状态；条件、优先级、进入/退出、打断及转换；将逻辑动作解析成播放/混合请求 | 逐骨骼采样、矩阵计算、重定向数学和 GPU 蒙皮 |
| 业务 TS | 从移动、战斗等系统取得事实，提交速度、落地、瞄准、受伤等参数或一次性信号 | 每帧选择动作名、调用 CrossFade 或重复驱动状态机 |

资源与状态机分别可以复用：更换动作资源不必重写业务；更换状态机策略不必修改骨架；更换角色骨架由适配配置处理。业务参数的名称及含义由项目定义，核心不识别武器、角色或状态名称。

## 自定义状态机脚本

脚本基类提供参数、当前状态、转换调度及绑定生命周期。项目通过继承定义自己的机器；状态、条件和转换可组合，具有实际复用需求的行为可以封装子类。简单比较先用同步谓词或已有条件组合，避免为每个阈值和动作建立一种原生类型。

建议的职责是：

- 机器负责保存每实例输入与当前状态，按稳定顺序评估转换，处理触发器、优先级和打断。
- 状态负责进入、更新和退出；片段状态可在进入时请求播放，移动状态可根据参数调节播放速度或混合权重。
- 转换连接源和目标，持有条件与过渡时间；多个条件读取同一份本次参数快照。判定本身不修改场景或播放状态，获选后才提交转换。
- 子状态机适合复用一组相关状态；首期不为尚无用例的层级建立通用图编辑器或另一套资源系统。

例如，业务提交实际移动速度、落地状态和攻击信号；自定义状态机脚本判断何时由移动进入攻击、何时按动作完成情况返回移动。判断留在该脚本中，业务不需要知道当前动画名称和过渡时间。

### TS 公开范围

状态机能力完整暴露给 TS，项目可直接继承基类、定义状态和条件并登记转换，不限于提供一个原生机器的播放按钮。

| TS 能力 | 使用方式 |
| --- | --- |
| 状态机与状态基类 | 从 `engine` 脚本模块导出，供项目 TS 继承、组合和复用 |
| 参数与触发器 | 提供有类型的读取、提交和复位；业务通过 Animator 组件的参数入口传入 |
| 条件与转换 | TS 定义同步条件，添加源/目标、优先级、过渡时间与打断规则；机器内部自动评估 |
| 生命周期 | TS 可定义进入、更新和退出逻辑；宿主自动驱动，暂停、解绑与清理遵守当前 Run/组件身份 |
| 动画执行 | 状态机脚本经 Animator 组件调用播放、混合、IK 目标与权重及所需只读查询；骨骼计算和重定向仍归 C++ |
| 挂点与事件 | TS 经组件取得命名挂点的变换副本、配置挂件跟随，注入事件标记及订阅/解除动画事件；回调不进入采样线程 |

实现时在 `include/engine.d.ts` 统一维护已实现的类型与方法，并同步绑定和类图；本设计不提前加入没有绑定实现的声明。业务只传参数的边界不变，状态机脚本与业务脚本仍为独立模块。

### 大规模敌人的复用

同类敌人共享**只读状态机定义**，每个敌人只持有**独立的轻量运行上下文**。例如 128 个相同类型敌人对应一份定义与 128 份上下文，不创建 128 套状态/条件/转换对象树，也不让它们共享一个正在播放的机器实例。该数量只是设计示例，不是已通过的性能指标。

| 共享内容 | 独立内容 |
| --- | --- |
| 状态、条件和转换的代码、只读配置及索引表 | 每个敌人的参数、当前状态、状态计时和未消费触发器 |
| 动作别名定义；同源动作、骨架及相同源/目标适配配置的不可变编译缓存 | 目标 Animator 身份、动作绑定的实例差异、原生播放时间及过渡进度 |
| 同一 Run 的模块、类定义和虚拟机 | 每个 Animator 的 Ozz SamplingContext、可变姿态和蒙皮输出 |

定义在同一 Run 内按控制器类型和显式配置版本构建并校验一次；参数名、状态名和转换关系可在构建时解析为索引，更新时只检查当前状态的出边及约定的全局转换。不同机器配置保留各自定义，不因为使用同一基类就错误合并。停止或热重载销毁旧 Run 的定义与上下文，不能跨虚拟机保存脚本对象。

可继承的状态/条件子类作为共享行为使用：回调接收当前敌人的上下文，不把角色、计时器、触发器或原生借用保存在共享对象及捕获闭包中。需要逐角色的自定义临时变量放各自上下文；共享定义一经构建保持只读，进入某敌人的状态不能改写其他敌人的条件和配置。

回调上下文仅在当前同步调用期间借用，不能保存、await 或返回 Promise；只读冻结也不能代替对闭包和实例字段的隔离约定。回调中新建、删除、解绑及切场景须在安全点维护实例集合，执行前后校验 Run、完整 Node 和组件实例身份；本次评估期间的新参数留到下次评估，避免遍历顺序影响转换。脚本异常处理沿用当前 Run 的失败与清理策略，不预先承诺单个敌人的异常隔离。

驱动继续放在既有 ScriptSystem：每个 Run 每帧统一进入一次动画状态机更新，在脚本内部遍历当前有效上下文，不为每个敌人创建 VM 或单独跨语言调用 update。参数支持一次提交多项并复用实例缓冲；动作切换只在转换时提交，播放速度、混合权重等连续量按变化提交，不在每帧重复 CrossFade。需要批量读取播放结果或提交请求时，补最小的通用组件批处理契约，保持 TS 条件判断与原生姿态计算的边界。

实例隔离仍须覆盖以下情形：

- 一个敌人的攻击/死亡触发器、计时或参数变化不能影响同定义的其他敌人；不同角色可以在相同状态处于不同播放相位。
- 对象池复用须显式重置上下文、触发器和待处理事件，并校验本次绑定身份，避免上一条生命的回调修改新敌人。实体销毁、组件重建和 Run 切换仍执行既有身份检查与清理。
- 参数未变化不等于不需要更新：动作完成、退出时间及状态超时仍会触发转换。隐藏或屏外不等于停用，不能仅以是否可见停止必要的状态推进和完成通知。
- 可并行的 Ozz 采样/混合继续使用现有 TaskSystem 批次；条件及脚本回调仍在当前 Run 主线程执行。共享代码和资源不代表可共享可变采样缓存或姿态缓冲。

### 接入现有引擎

1. 自定义机器位于项目 `assets/scripts/animation/`，作为普通 TS 模块静态导入。资源声明继续经现有导入、GUID 与出包链路，不扫描任意脚本文字猜测动作依赖。
2. 通过 `Animator` 组件完成一次装配并提供业务参数入口。机器是可选功能，未绑定时保持当前手动播放器；绑定后明确播放控制权，避免机器和业务同时操作同一 Animator。
3. 通用脚本基类可参考脚本插件已有 `UiControllerBinding` 的组织方式：由 `engine` 脚本模块导出，共用当前 Run 和虚拟机，不向核心保存 TS 对象或虚拟机句柄。
4. `ScriptSystem` 在业务更新后自动驱动绑定机器，随后按现有宿主顺序执行 C++ `AnimationSystem`。业务无需再调用每个机器的 update，不新增独立执行器、Manager 或线程池。
5. Run 内的机器以 Scene、完整 Node 与 Animator 组件实例身份绑定；再次取得组件句柄仍指向同一机器，删除后添加的组件不能复活旧绑定。控制器脚本的临时状态随 Run 管理；原生播放、混合和姿态状态仍唯一存于现有 ECS/动画系统。

建议先以静态导入类装配，复用现有模块预检与打包。若后续要求在编辑器按资源路径选择控制器脚本，再单独评审组件持久引用、模块构造和热重载契约；不把另一套脚本装载器当作首期前置条件。

### 转换与生命周期

- 每次更新按明确优先级和稳定登记顺序选一个转换，限制当次转换次数，拒绝同帧无限循环。全局转换与局部转换的优先关系由机器定义。
- 触发器只在转换成功获选并被执行器接纳后消费；停止、解绑与 Run 重建清理旧信号。条件不能靠读取先后顺序相互吞掉触发器。
- 动作加载或骨架绑定失败不能先把脚本当前状态改成目标；失败须保持可恢复的状态并报告原因。已有 CrossFade 的失败保持、打断姿态冻结继续复用。
- 动作时间来自执行器。现有非循环片段播放结束会变为 paused，不能因此停止机器判断，也不能只以 `isPlaying` 为驱动条件。需补明确的时长/完成查询或等价最小通知，区分结束、显式暂停、停止与打断。
- 世界暂停、组件停用和机器显式暂停冻结相应判断及计时；暂停菜单仍由脚本正常处理。组件恢复保留各自状态，不用全局停止 ScriptSystem 代替世界暂停。
- 删除对象、移除组件、卸载场景和停止 Run 清理绑定；有效常驻节点按既有场景归属保留。热重载清理旧 Run 后重新装配，不保留旧 VM 的机器对象。
- 条件及事件回调在当前 Run 的主线程安全点执行，禁止在 Ozz worker 调用 TS。动画时间标记事件另需跨循环区间与去重语义，不能用进入/退出回调代替所有动画事件。

## 动画资源重定向

这里的重定向指**同一源动作驱动不同目标骨架**，包括不同骨名、参考姿态、骨轴及体型比例；不是资源路径改名，也不是只把轨道数组重新排序。

资源层应保留源动作及源骨架，目标模型保留自身骨架、绑定姿态和蒙皮权重。适配配置显式描述源/目标的关节语义与骨链、参考姿态、骨轴和坐标修正、root/hips 平移及比例策略、附加骨骼处理。源动作、源骨架、目标骨架与适配配置都经正常 GUID、依赖和增量管线使用，不覆盖原购买资源。

编辑器负责生成、校验和预览配置；允许人工修正含糊对应，缺少必要骨链则报告失败。运行时 C++ 只执行明确配置，不根据模型名字猜测处理方式。状态机脚本调用逻辑动作，不包含角色骨名或逐骨修正。

执行顺序为：

1. Ozz 采样源动作，按所选算法生成必要的源姿态空间数据。
2. 按适配配置转换到目标骨架的局部姿态；保留目标肢体长度，按明确定义处理 hips/root，不能把源平移轨道直接覆盖所有目标骨长。
3. 不同来源的动作先统一为同一目标骨架，再进行普通、遮罩和加法混合。
4. 所需 IK 修正完成后生成最终模型矩阵和现有蒙皮 palette，交给已有 GPU 蒙皮。

加法动作须明确原参考姿态及差值语义；重定向后也应在目标参考姿态下得到对应差值，不能把普通绝对姿态直接传入 Ozz additive layers。该部分与参考姿态补偿一并校验。

适配结果缓存必须包含源/目标骨架、适配配置及相关资源代际。层级、参考姿态、骨轴或导入坐标变化后失效；共享不可变配置，每角色采样与姿态缓冲独立。运行时真正共享源动作，不能以为每个角色离线烘焙一份片段代替该能力。

首期建议以普通人形和 InPlace 为验收范围，至少让同一组源动作驱动两个目标角色，样例共同覆盖骨名、身高/肢体比例及 A/T 参考姿态差异。默认仍由物理/导航移动节点。RootMotion、接触脚锁和武器握持 IK 需要各自明确契约，不能用“已支持重定向”概括它们。完整制作与验收要求见[角色与动画制作](../editor/character-production.md)。

## IK 与骨骼挂点

当前只有 Ozz 基础采样/过渡与蒙皮，尚未接入运行时 IK、骨骼挂点组件或对应 TS 查询。以下是本次需要补齐的设计范围，不能从第三方库已有 job 推断本引擎已经具备该功能。

### IK 的归属和输入

基础瞄准与两段肢体 IK 复用 Ozz `IKAimJob`、`IKTwoBoneJob`，在核心动画的姿态链中执行。资源保存骨链、关节方向/弯曲轴、偏移和约束默认值；Animator 暴露对应目标、权重和开关，由项目 TS 设置。目标须明确坐标空间，节点目标须校验实体身份；目标点与 pole vector 转到目标骨架模型空间，forward/up/mid 轴按关节局部空间解释，求解校正写回局部旋转，不能把世界坐标或外部骨索引直接作为已匹配输入。

状态机脚本可以根据参数调节约束权重；业务传入瞄准点、握持目标等事实，不逐骨计算修正。所有可选约束默认关闭。IK 只修改角色骨姿态，不抢占物理/导航对角色根节点的位置控制权。

编辑器动画插件负责骨链/目标/方向可视化、配置与预览，运行时不做骨名猜测。足底接触还需要地面查询、接触保持及目标平滑，两段 IK 本身不等于完整脚锁；完整握持还需末端手掌朝向约束。复杂全身求解器若确需接入，可按最小契约另行注入，不先为每种 Ozz job 建立独立插件或 System。

### 骨骼挂点与组件

资源定义命名挂点，保存目标骨路径/语义键和骨局部偏移；运行骨索引只作代际受控的解析缓存。通用挂点随目标骨架/角色配置复用，装备或实例的额外偏移由预制体/组件覆盖，不把某个武器名称写入核心。

`BoneAttachment` 是最小值句柄组件，挂在武器、挂件或特效所在的普通 Node 上，保存来源 Animator 节点、挂点名、偏移及默认关闭的跟随属性。原 Node/ChildOf 仍负责组织与生命周期，骨骼不展开为海量场景节点。TS 通过该组件绑定/解除跟随，或通过 Animator 取得命名挂点的已提交变换副本。

挂点必须使用**最终目标骨架的关节模型矩阵**，不能使用含 inverse-bind 的 skinning palette。按当前引擎空间约定，设 `B=mesh_to_skeleton`、`G=最终关节模型矩阵`、`W=Mesh 节点世界矩阵`、`O=挂点偏移`，则：

```text
BoneWorld       = W * inverse(B) * G
AttachmentWorld = BoneWorld * O
AttachmentLocal = inverse(ParentWorld) * AttachmentWorld
```

来源 Animator、MeshRenderer 组件实例或目标骨架/网格资源换代后重新解析；缺骨、歧义或旧身份明确失败，不选择同名首骨。查询不借出 worker 缓冲、Ozz 指针或内部 span。持久作者偏移与每帧跟随结果分开，保存不能将当前动作姿态当成新的绑定偏移。

暂停保留最终骨姿态，角色根变换改变时仍需更新挂点世界位置。停止后挂点应与显示的绑定姿态一致，不能继续沿用旧动作骨矩阵。镜像、非均匀缩放和无法用现有 TRS 表达的剪切必须有明确策略或拒绝，不能静默近似为正确挂点。

### 同帧顺序与控制权

标准顺序为采样、重定向、混合、必要的模型姿态计算、有序 IK、最终骨姿态提交，再发布挂点与蒙皮输出。求解某条骨链后重新计算受影响的模型姿态；渲染与挂点使用同一份已提交最终结果。

双手持物需选择明确的依赖方向：先用独立瞄准目标求主手/上身，推导主手挂点上的道具姿态，再从道具局部握点得到副手目标，最后只求解不会反向改变主手依赖的副手链。若约束共享祖先而无法按此分离，须使用独立道具目标或明确的联合求解器；不能让双手分别从受自己控制的道具求目标形成环，也不能用上一帧挂点隐藏依赖问题。

挂件 Transform 由跟随组件负责时，不得同时由动态刚体、角色控制或导航写入；掉落先解除跟随、保留最终世界姿态，再移交物理。首期视觉挂件与动态物理挂接区分；带碰撞的 kinematic 跟随还须对齐物理同步安全点，不能仅写 Transform 就声称碰撞已同步。挂点/父链依赖环明确拒绝。

相同目标骨架及资源代际的敌人共享骨链、挂点定义和关节解析结果，但 IK 目标、权重、临时姿态与跟随状态独立。每帧在原生批次中处理实际启用的约束和挂点，不由 TS 逐骨轮询；屏外仍被挂件、射击起点或事件需要的骨姿态不能因未绘制而静默停止更新。

## 动画事件与注入

动画时间事件和状态机进入/退出是两类通知。前者绑定动作播放进度，例如脚步或换弹时间点；后者绑定逻辑状态转换。二者分别提供，不用状态回调冒充动作标记。

### 事件数据与 TS 注入

- 编辑器时间线可制作事件标记，写入动作关联配置并由正常导入生成纯数据事件轨：时间、稳定标记身份、事件名及有类型的载荷。帧号输入须按源动作采样率转成时间，不能依赖游戏帧率。事件不保存 JS 函数、对象地址或玩法规则。
- TS 也可为动作绑定追加事件标记。追加形成可复用的只读事件轨定义或实例覆层，不改写共享源动作；仅对某敌人注入的标记不能影响其他敌人。配置、资源代际及绑定版本变化须重新校验时间范围。
- TS 经 Animator 组件订阅/解除事件，订阅属于当前 Run 和 Animator 组件实例；事件处理由自定义状态机或业务模块按职责提供。核心不按事件名称执行伤害、补弹、音效或特效策略。

### 核心收集，宿主注入接收端

核心根据真实动作推进区间收集事件值；宿主注入可空事件接收回调，脚本插件将事件派发给对应 Run 的订阅者。这里只增加动画结果出口，不建立通用 EventBus，也不强制核心依赖脚本/音频/特效插件。

事件至少带来源 Scene/完整 Node/Animator 实例、播放实例代次、动作资源代际、标记身份、周期/时间和层来源。采样任务只产生值记录；等待相关任务成功、最终姿态和挂点发布后，在主线程安全点分发。接收回调不在 ECS 遍历或 worker 内执行，结构修改按安全点提交；每次分发检查旧 Run、旧播放/组件身份和对象池重用，丢弃过期事件。

分发时机须作为契约明确：本方案要求宿主提供动画/挂点提交后的安全点，不能声称现有“业务 Update 前分发”已经实现同帧动画事件。事件回调引发的新动画参数在下一次状态机求值生效，不通过重入采样在同帧反复修改姿态。

### 时间、混合与去重

- 正向播放按跨越区间处理，并为新播放实例的零时刻标记单独定义一次性起点规则；末帧及下一圈起点必须保持唯一周期归属。非循环完成只发一次，保持末帧不重复发。
- 保留周期计数或未取模推进信息，正确覆盖一次更新跨多圈的情况；不能使用当前已取模的 time 反推全部事件。设定队列预算时须显式报告溢出，不静默漏掉事件并返回成功。
- Seek 默认只定位，不补发沿路业务事件；暂停、零速不产生新的时间跨越；停止/重播/绑定重置清理旧待发记录并使用新的播放身份。倒放只有在正式支持后按反向时间顺序定义，不能把正向算法直接套用。
- 过渡、BlendSpace、Mask 和 Additive 需要明确事件所有权。首期双动作过渡可约定只由目标播放实例产生业务标记，来源只参与姿态混合；多层后续显式指定事件来源，不因所有输入都被采样而重复发副作用。
- 去重按播放实例、资源/标记身份及周期进行，不能只按事件名；一个动作里多个同名脚步标记是合法事件。订阅回调同步执行并复用 Run 的失败清理策略，不承诺未实现的逐敌人异常隔离。

同类敌人共享事件轨与监听代码，各自独立记录播放区间和已消费位置。只为实际跨越的标记生成记录，避免为每敌人每事件复制一套监听对象；隐藏、姿态降频与 GPU 未绘制不能直接取消必要的事件时间推进。

## 核心、插件与编辑器边界

按数据和执行职责划分，允许用最小契约注入可选实现。下表中的重定向插件与动画制作插件为建议落点，尚未创建；不将所有动画功能搬成一个新系统，也不为每个动作或算法建立插件。

| 所属层级 | 本次功能归属 |
| --- | --- |
| 运行时核心 `runtime/animation`、Animator/挂点组件 | 原生播放时钟、过渡、共享编译缓存、Ozz 采样/混合/Mask/Additive/基础 IK、最终骨姿态、挂点及 palette；组织采样后、混合前的重定向调用，按时间区间输出事件值 |
| 运行时核心 schema / resource | 骨架、动作、适配配置、骨链/挂点/事件轨的最小生成数据及单项读取契约；GUID、目录、资源代际和正式依赖，不含源格式解析和制作策略 |
| 现有 `runtime/script` 插件 | TS 状态机/状态/条件的公开外观、共享定义、逐敌人上下文、Run 自动驱动和组件绑定；事件注入/订阅/清理；项目转换规则仍在自定义 TS |
| 可选 `runtime/animation_retarget` 插件 | 选定重定向算法的具体实现、私有预处理与适配；经核心契约注入，不依赖脚本、编辑器或具体项目 |
| 编辑器基础 `editor/` | 通用资源管线、Importer 登记、任务、事务/撤销、项目环境与预览宿主；不包含具体动画算法和制作面板 |

运行属性和资源引用经 Animator 等所属组件暴露，默认不隐式启用可选能力。项目获取组件调整参数，不直接取得求解器或插件服务。编辑/诊断工具通过 MCP 操作；预览调用同一核心 Animator/Ozz/重定向链，不建立另一套动画播放器。

### 注入的范围与所有权

- 脚本执行沿用宿主已有 `ScriptRuntimeFactory` 注入；资源加载沿用 `ResourceLoader`。状态机功能补入现有脚本插件和 Run，不为它新增一套脚本 Driver 或 VM。
- 动画事件用一个可空接收回调注入，批量交付纯值结果；宿主在动画/挂点发布后的安全点调用它。订阅和 VM 对象留在脚本插件，结束 Run 解除订阅，接收端释放前先终止分发；核心不持有项目回调或按事件名分派业务。
- 对可选重定向，核心只声明“准备不可变绑定、按源姿态与显式配置转换到目标姿态”的最小契约，具体实现由宿主选择并注入。契约使用引擎数据，不公开第三方求解器、Ozz 类型或 VM 类型；Profile 只包含真实映射、参考姿态和处理策略，不预先建立求解器图或动态能力注册框架。
- 建议由宿主的可空工厂创建提供者，交给 AnimationSystem 独占；未选择工厂表示功能未装配，已选择工厂但创建/初始化失败则明确失败，不能静默当成关闭。不把具体插件选择塞进 EngineConfig、Scene 或核心自动发现流程。提供者以世界/动画系统为生命周期，供所有角色复用，而不是每敌人创建一个。
- 不可变预处理映射按源/目标/配置及资源代际共享；并行计算只消费稳定快照和独占输出。回收前先完成已提交任务，不能在 worker 使用已释放配置或跨 ECS 结构变更保留原生列借用。
- 核心没有提供者时保持普通播放与现有合法绑定路径。组件显式请求跨骨架重定向但没有提供者时，在组件提交/预检阶段返回明确的不支持状态，不等到 worker 才发现缺少能力；不静默复制源局部 TRS 伪装成功。调用失败不发布半成品姿态。
- 编辑器动画工具只依赖核心契约与已有编辑器接口，预览使用同一个已注入实现；不为打开面板强制装配脚本或依赖图插件。能力不可用时显示原因，宿主负责选择实现。
- Ozz 已有的采样、混合及 IK 直接复用，不为这些现成 job 逐项添加接口包装。新注入契约只用于本次确有可选实现需求的环节，不扩成通用后端框架。

具体接口、资源模型及宿主工厂改动在所属类图评审后实施。启用/禁用插件时须分别验证目标与链接边界；不装配脚本/重定向/编辑器制作插件的程序仍应能够播放普通动画，启用后的功能则须实际运行，不能只以成功登记作为验收。

## 实施顺序与验收建议

1. 先评审最小脚本基类、共享定义/实例上下文、Animator 绑定/参数入口及播放完成查询。用公开范例验证业务只传参数、同定义多敌人独立转换、生成/回收/复用隔离、条件优先级、打断、暂停和生命周期；保留现有 Ozz/CrossFade/GPU 路径。
2. 资源侧明确适配配置与目标骨架契约，接入运行时人形重定向。以同一动作库、同一状态机驱动至少两个不同骨架，检查参考姿态、比例、关节和资源热重载；默认 InPlace。
3. 明确基础 IK、最终骨姿态查询和 BoneAttachment 组件。验证瞄准/双手目标顺序、武器与特效跟随、不同父节点下的空间转换、资源换代、暂停/停止及解除跟随后掉落。
4. 接入事件轨和运行时注入、宿主安全点接收及 Run 订阅。验证跨循环/多圈、结束、Seek、暂停、过渡事件归属，以及多敌人/对象池/旧 Run 的事件隔离。
5. 按实际角色需要扩展原生多动作混合、1D/2D、Mask、Additive 和接触/全身求解。复用 Ozz 及上游已验证算法，基类接口保持可扩展，不先搬完整图编辑器或另一引擎对象体系。

## 当前实现入口与边界

- 业务通过 `Animator.SetStateMachine(sharedDefinition, aliases)` 装配，通过 `SetParameters`、`Trigger` 提交事实；ScriptSystem 自动更新。定义共享，参数、状态、时钟与触发器逐实例隔离。同一 Animator 的其他包装句柄仍访问同一机器。
- 新状态用 `PlayAnimation` 的原子请求提交，失败保留旧动作；机器取得播放控制权时，业务手动 `Play/CrossFade/SetSpeed` 等返回失败。解绑后可恢复手动播放。
- 原生 Ozz 依次执行源采样、可选 profile 重定向、两动作混合、有序 Aim／TwoBone IK、最终模型矩阵和 GPU palette。`ik_enabled` 与 `BoneAttachment.follow_enabled` 默认关闭。
- `.retarget` 是独立 GUID 资源，由 `editor/animation_tools` 导入；`runtime/animation_retarget` 为可选提供者。实现适配固定版本 Wicked Engine 的模型空间参考姿态转换，来源及 MIT 许可见 `third_party/notices/wicked-animation-retarget.md`。
- FBX 邻接 meta 保存 sockets、IK 定义与事件轨。制作 MCP 修改源 meta 并支持撤销；回执的 `reimportPending` 只表示等待正常导入，不表示缓存已发布。[制作接口](../plugins/editor/class-diagrams/animation-authoring.md)说明字段与命令。
- TS 用 `SetEventMarkers` 追加实例事件轨，用 `SubscribeEvents/UnsubscribeEvents` 管理同步监听；Seek 不补发经过的事件。原生完成主线程提交后统一分发，Run、角色、组件、播放和资源身份都参与失效检查。

公开范例的 `scripts/animation/locomotion_machine.ts` 保存一个共享定义，courtyard 的角色业务只提交速度。Idle 暂用 walk 首帧停播，不将临时姿态宣称为新制作的待机动作。

首期覆盖普通状态与两动作过渡、显式参考姿态重定向、基础 Aim/TwoBone、命名 socket 和标量时间事件。层级状态机、混合树、遮罩／加法层编辑、接触脚锁、全身 IK、RootMotion 驱动及跨 Actor 动画目标依赖不在本次完成范围。编辑器交互统一采用 MCP 与配置文件，窗口仅提供场景预览／运行，不规划编辑器面板、时间线或图形状态机编辑器。当前实例隔离测试不能代替大规模敌人的性能验收。
