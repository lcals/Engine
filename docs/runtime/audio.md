# 运行时音频

[音频系统类图](class-diagrams/audio-system.md) · [音频组件类图](class-diagrams/audio-components.md)

场景通过 `Node + AudioSource` 表达声源，通过 `Node + AudioListener` 表达监听器；位置和朝向来自同一节点的 `Transform` 世界矩阵。组件只保存 FlatBuffers 生成的设置、音频资源引用和瞬时播放请求。`AudioSystem` 借用世界，在主线程处理这些请求并向 SDL3 音频流提交数据，SDL 音频线程不访问场景对象。

音频源文件由编辑器导入为 `AudioClipData`：交错排列的 F32 PCM，记录采样率、单声道或双声道及帧数。运行时通过统一资源目录和加载接口获得音频，不解码 WAV、不扫描工程，也不依赖编辑器和 MCP。

音量、音调、循环和衰减设置可以在播放中修改；相同 clip 的 `set_settings()` 或 `restore_data()` 保留播放与暂停状态。成功更换 clip 才停止旧播放，失败保留原设置、资源和状态。

`AudioSource::play()` 返回请求是否被接受；缺少音频时返回失败。接受后状态为 `pending`，SDL 设备和流真正就绪后才变为 `playing`。设备初始化或流提交失败时，状态为 `failed`，`AudioSystem::tick()` 返回失败并提供 `last_error()`；不会以静音设备回退伪装播放成功。`playing()` 仅在状态为 `playing` 时为真。

- `play()` 从停止或播放中重新开始；暂停后调用则续播。
- `pause()` 暂停待播放或正在播放的源，保留流内进度；`stop()` 清除请求，下一次音频更新销毁该源的流。
- `play_on_awake` 在每个组件实例首次被音频系统观察为启用时消费一次；当时没有 clip 就不播放。设置 clip、重新启用、播放结束或系统 `clear()` 都不会重复触发。
- 更换 clip 成功后停止原播放；读取失败保留原设置、资源和状态。音量、音调及空间设置变化不重置播放进度。
- 音量和监听器总音量为 `[0, 1]`，音调倍率为 `[0.01, 4]`；距离必须有限，`0 <= min_distance < max_distance`。空 GUID 表示未设置 clip。
- 同一场景有多个启用监听器时，按场景节点顺序采用第一个。空间声源没有有效监听器时静音但仍推进时间；非空间声源不需要监听器。
- 空间声源在最小距离内保持音量，最大距离外静音，中间线性衰减；按监听器世界右方向计算左右声道平衡。双声道空间声源先取均值再定位；非空间双声道保留原声道。

系统按需打开一个 SDL 逻辑输出设备，每个正在播放或暂停的声源拥有独立音频流。短队列由主线程补充，循环由帧游标回绕，音调使用 SDL 频率倍率，音量使用流增益。暂停单个源只解绑该源；宿主进入后台调用 `set_paused(true)` 暂停整个输出设备，返回前台恢复，不改写组件播放请求。

系统只记录场景 ID、节点 ID、资源修订和播放游标，不跨帧借用节点或组件指针。禁用或删除节点、切换场景会在下一次音频更新清理旧流；宿主结束玩法或关闭世界前调用 `clear()`，同步销毁全部流和设备。`clear()`、关闭和部分初始化失败均可重复清理。首次播放前不打开设备；最后一个声源自然结束只释放流，保留当前场景的设备，避免截断已经混入硬件输出缓冲的尾音。设备随场景切换、`clear()` 或关闭释放。

自动回归使用 SDL 的 dummy 输出，检查真实音频流消耗、循环、暂停、停止、失败及释放；这不代表真实设备的扬声器或人工听觉验证。系统不涉及录音、麦克风、音频总线、混响或平台专有音频策略。
