# 资源目录、构建与同步加载

[类图索引](../class-diagrams/index.md) · [资源系统](class-diagrams/resource-system.md) · [编辑器资源构建](../editor/resource-build.md)

资源目录、定位和实体数据分离。核心按需同步加载必要依赖，编辑器与运行时宿主通过同一目录和加载接口驱动核心。

## 核心与调用方

遵循全引擎的[调用方驱动核心](../architecture.md#调用方驱动核心)原则：业务与编辑器均使用核心最小能力，自己组合流程。下表的目录更新次数只是应用示例，不是核心需要识别的模式或特殊机制。

核心只提供清单更新、元数据查询、文件读取、同步加载和资源共享。不识别编辑器模式，不扫描 assets，不监听文件，不读取项目打包设置，不发现或自动切换发布版本。

| 职责 | 编辑器 | 真机正常运行 |
| --- | --- | --- |
| 资源范围 | 收集 assets 下全部源资源及唯一 meta 身份 | 构建选定入口与必要依赖的精简集合 |
| 清单形成 | 扫描和增量导入后，直接向核心提交完整目录数据 | 启动读取随包生成的运行清单，向核心提交一次 |
| 清单变化 | 编辑器处理新增、修改、移动、删除并再次提交 | 正常运行期间固定，不扫描源工程 |
| 存储 | 直接使用转换缓存，不要求打包 | 独立资源文件或合并包 |
| 加载和释放 | 两端共用同一实现 | 与编辑器相同 |

编辑器直接调用 `update_catalog(data, mounts)`，无需为了更新内存目录先打包、序列化再读回。真机宿主解码 FlatBuffers 运行清单后调用同一接口。MCP 调试同步是显式部署操作，由宿主协调应用，不给核心添加编辑器业务。

## 清单与身份

- 项目打包清单位于 `settings/`，维护入口、保留项和分包规则，只在编辑器使用。
- 编辑器完整资产目录登记全部源资源的身份、类型和导入状态。源代码和 include 等构建输入也被登记，但不会因此成为运行依赖；没有可用产物的资源不能伪装成可加载资源。
- 核心运行目录包含虚拟路径、完整 GUID、类型、格式版本、内容哈希、必要运行依赖和存储位置。编辑器提交完整可用集合，发布包提交选定子集；模型与查询接口相同。
- `GuidMap` 保留在核心，负责 `builtin/`、`project/` 路径与 GUID 的双向映射。移动保留 meta 身份，复制必须得到新 GUID。
- 内置资源使用固定 GUID；项目可引用内置，内置不能反向引用项目。打包必须验证依赖由项目产物或指定内置资源集合提供。
- 目录、定位和实体头由 `include/schemas/runtime/` 下的 FlatBuffers 模型定义，不再手写持久数据模型。

正式转换缓存仍为 `cache/gen/<完整GUID>`，无扩展名、类型前缀或版本子目录。SQLite 与目录清单放在 cache 根。独立文件沿用 GUID，合并包只改变资源位置。

## 索引与实体分离

访问顺序为“虚拟路径 → GUID → 清单条目 → 挂载及文件范围 → 资源实体”。

加载清单只验证元数据和依赖、建立索引，不逐个打开实体，不读取全部资源或整包。读取实体头只校验头部，不创建资源、不加载依赖。`load()` 才读取并解析资源及必要依赖。

[VirtualFileSystem](class-diagrams/virtual-file-system.md) 使用 SDL3 同步访问普通文件、包内字节范围和 Android 内置文件。它只认识挂载与文件位置，不认识 GUID、场景、编辑器或依赖图。实际路径由现有 App 接口及宿主提供。

## 同步加载与释放

业务只加载顶级资源；核心先加载其必要运行依赖，再建立当前资源。内部是允许共享的依赖图，必要依赖循环或缺失时失败。供以后使用的路径/GUID 引用不自动加载；可能动态使用的资源由打包清单明确保留。

`load()` 返回 bool，成功输出 `std::shared_ptr<const Resource>`；失败输出为空，释放本次新增引用，不影响其他使用者。对象索引仅持 `weak_ptr`，相同资源由实际使用者共享，每个资源持有直接必要依赖的共享引用。

业务释放自己的 shared_ptr 即卸载一次使用引用。最后一个使用者释放后，先销毁当前数据，再释放依赖引用；共享依赖不会提前销毁。不另建引用计数、通用 Result、异步请求或优先级框架。

Scene 持有场景根资源；MeshRenderer、Material 和脚本运行也持有它们实际使用的资源。动态换网格、材质或 Shader 时，先成功取得新引用，再替换并释放旧引用。资源对象保存独立元数据和解析结果，不借用会被替换的目录条目。

加载成功表示 CPU 资源和必要依赖可用。节点实例化归 World/Scene，脚本执行归 ScriptSystem，GPU 创建和退役归 RenderSystem；上层启动流程继续检查这些步骤。Engine 只管理系统生命周期。

## 更新与发布边界

`update_catalog()` 校验完整候选及挂载，成功整体替换，失败保留旧索引。仍有使用者的资源及依赖不允许改变或删除其内容、类型、大小、路径、存储位置、依赖集合，对应挂载也不能换指向。未被使用且不影响已有依赖的条目可直接更新。

该规则不能阻止外部先覆盖文件。编辑器须在发布变化的 cache/gen 文件或包之前协调停止并释放受影响使用者，再发布产物、直接更新目录，最后按编辑器业务需要恢复项目。转换失败保留旧正式产物；更新失败应恢复匹配的旧产物与目录，或保持项目停止。

核心不隐式停止项目、不执行脚本回调、不自动恢复项目。第一版不引入多版本实例共存框架。真机正常启动只提交一次清单；MCP 调试先准备完整候选内容到 App 持久可写目录，再由宿主显式应用，不能提前覆盖活跃包。

持久版本优先由宿主选择。核心只按本次明确提交的目录和挂载读取，缺失条目不得私自回退并复活已删除资源。

## 兼容范围

资源目录使用版本 2，导入器会重新生成对应实体。旧版本目录不能直接加载，重新导入项目后再构建或同步。目录提交不逐个读取实体；完整部署校验由构建或同步调用方完成。

公开方法和所有权在[独立类图](../class-diagrams/index.md#资源系统)维护；场景、组件与脚本的资源引用关系见[领域使用者](class-diagrams/resource-system.md#领域使用者)。
