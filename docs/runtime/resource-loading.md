# 资源目录、构建与加载

[类图索引](../class-diagrams/index.md) · [资源系统](class-diagrams/resource-system.md) · [编辑器资源构建](../plugins/editor/resource-build.md)

资源目录、定位和实体数据分离。核心提供单项同步加载和显式后台加载，运行时资源依赖图插件组合必要依赖、共享缓存和反向释放；编辑器与运行宿主使用同一目录和加载接口。

## 核心与调用方

遵循全引擎的[调用方驱动核心](../architecture.md#调用方驱动核心)原则：业务与编辑器均使用核心最小能力，自己组合流程。下表的目录更新次数只是应用示例，不是核心需要识别的模式或特殊机制。

核心只提供清单更新、元数据查询、文件读取、单项加载及 ResourceLoader 抽象接口。不识别编辑器模式，不扫描 assets，不监听文件，不读取项目打包设置，不发现或自动切换发布版本。

| 职责 | 编辑器 | 真机正常运行 |
| --- | --- | --- |
| 资源范围 | 收集 assets 下全部源资源及唯一 meta 身份 | 无清单默认全部；有清单为入口与必要依赖的集合，并包含引擎基线资源 |
| 清单形成 | 扫描和增量导入后，直接向核心提交完整目录数据 | 启动读取随包生成的运行清单，向核心提交一次 |
| 清单变化 | 编辑器处理新增、修改、移动、删除并再次提交 | 正常运行期间固定，不扫描源工程 |
| 存储 | 直接使用转换缓存，不要求打包 | 独立资源文件或合并包 |
| 加载和释放 | 两端共用同一实现 | 与编辑器相同 |

编辑器直接调用 `update_catalog(data, mounts)`，无需为了更新内存目录先打包、序列化再读回。真机宿主解码 FlatBuffers 运行清单后调用同一接口。MCP 调试同步是显式部署操作，由宿主协调应用，不给核心添加编辑器业务。

## 清单与身份

- 项目打包清单统一为 `settings/resource-build.toml`，维护入口、保留项和分包规则，只在编辑器使用；不维护平台资源副本。目标平台由构建调用传入，缺少清单或 `items` 时全量，有 `items` 时按真实依赖闭包筛选。
- 编辑器完整资产目录登记全部源资源的身份、类型和导入状态。源代码和 include 等构建输入也被登记，但不会因此成为运行依赖；没有可用产物的资源不能伪装成可加载资源。
- 核心运行目录包含虚拟路径、完整 GUID、类型、格式版本、内容哈希、必要运行依赖和存储位置。编辑器提交完整可用集合，发布包提交选定子集；模型与查询接口相同。
- `GuidMap` 保留在核心，负责普通相对路径、`builtin://` 路径与 GUID 的双向映射。普通资源名如 `scenes/main.scene`，不携带项目前缀。`editor://` 只预留给编辑器，运行目录和解码器拒绝它。移动保留 meta 身份，复制必须得到新 GUID。
- 内置资源使用固定 GUID；项目可引用内置，内置不能反向引用项目。打包必须验证依赖由项目产物或指定内置资源集合提供。
- 目录、定位和实体头由 `include/schemas/runtime/` 下的 FlatBuffers 模型定义，不再手写持久数据模型。

正式转换缓存仍为 `cache/gen/<完整GUID>`，无扩展名、类型前缀或版本子目录。SQLite 与目录清单放在 cache 根。独立文件沿用 GUID，合并包只改变资源位置。

## 统一资源根与引擎资源

`App::assets_path()` 返回应用包内读取根：Windows/macOS 原生程序使用程序旁 `assets/`，可选 macOS `.app` 使用 `Contents/Resources/assets/`，Android 为 `apk:/assets`。根下直接放 `catalog.bin` 及引用的 `packs/`、`gen/`，所有平台直接读取同一 catalog 契约。项目名不进入这个布局。编辑器显式把读取根覆盖为项目 `cache/`，不复制第二份导入缓存。

运行构建自动把 11 项固定引擎资源写入 `packs/builtin-*`。Shader 按目标平台重新编译，不能把 Windows 字节码复制给 Android。业务只使用 `builtin://...` 逻辑名，不维护内部包目录。

引擎无项目启动和编辑器导入仍可使用编入的 bootstrap 定义；有物理位置的目录条目必须读取实际实体，包括内置资源，缺失或损坏返回失败，不回退 bootstrap。`find_*` 也不能绕过当前目录直接返回编入定义。

## 索引与实体分离

访问顺序为“虚拟路径 → GUID → 清单条目 → 挂载及文件范围 → 资源实体”。

加载清单只验证元数据和依赖、建立索引，不逐个打开实体，不读取全部资源或整包。读取实体头只校验头部，不创建资源、不加载依赖。核心 `load()` 读取并解析单项，所选资源依赖图加载器才组合必要依赖。

[VirtualFileSystem](class-diagrams/virtual-file-system.md) 使用 SDL3 访问普通文件、包内字节范围和 Android 内置文件。同步接口直接读取，异步接口把路径校验与打开交给加载任务域，实际传输使用 SDL AsyncIO，完成事件由宿主线程轮询。它只认识挂载与文件位置，不认识 GUID、场景、编辑器或依赖图。实际路径由现有 App 接口及宿主提供。

## 同步加载与释放

业务通过 `ResourceSystem::loader()` 只请求顶级资源；ResourceGraphSystem 插件先加载必要运行依赖，再调用核心建立当前资源。内部是允许共享的依赖图，必要依赖循环或缺失时失败。供以后使用的路径/GUID 引用不自动加载；可能动态使用的资源由打包清单明确保留。

`load()` 返回 bool，成功输出 `std::shared_ptr<const Resource>`；失败输出为空，释放本次新增引用，不影响其他使用者。插件缓存仅持 `weak_ptr`；同代际相同资源由实际使用者共享。插件私有 Bundle 保存当前对象与直接依赖，使用 shared_ptr 别名构造返回 ResourcePtr；核心 Resource 不保存依赖。

业务释放自己的 shared_ptr 即卸载一次使用引用。最后一个使用者释放后，先销毁当前数据，再释放依赖引用；共享依赖不会提前销毁。不另建引用计数、通用 Result 或优先级调度框架；异步加载复用 ThreadSystem/TaskSystem 与 SDL。未启用依赖图插件时，加载器回退核心单项能力，核心不会悄悄实现另一套依赖遍历。

Scene 持有场景根资源；MeshRenderer、Material 和脚本运行也持有它们实际使用的资源。动态换网格、材质或 Shader 时，先成功取得新引用，再替换并释放旧引用。资源对象保存独立元数据和解析结果，不借用会被替换的目录条目。

加载成功表示 CPU 资源和所选加载器承诺的必要依赖可用。节点实例化归 World/Scene，脚本执行归 ScriptSystem，GPU 创建和退役归 RenderSystem；上层启动流程继续检查这些步骤。Engine 只管理系统生命周期。

## 后台加载与分帧提交

宿主从统一 RuntimeSettings 取得参数，向 ResourceSystem 配置加载任务域和[数量、字节及完成派发预算](parallelism.md)，依赖图的 `begin_load()` 随后使用后台路径。外置实体使用 SDL AsyncIO 读取，再由 oneTBB 任务校验与解码；内置 bootstrap 定义仍在宿主线程复制。依赖关系验证、缓存发布和完成委托在宿主线程进行，后台不访问活动场景或脚本 VM。

调用方跨帧 `step()`，未完成时返回 loading，不等待 future。资源计数达到 total 且 ready 后才提供完整根引用；后序依赖验证完成前不向共享缓存发布半个闭包。取消或目录换代立即放弃候选，已提交 I/O 与解码继续安全收尾，不能把旧结果发布进新目录。资源操作借用加载器与资源系统，必须先销毁操作，再关闭加载器和资源系统；异步资源收尾须早于所借用的任务域关闭。

脚本 `Scene.BeginLoad/StepLoad/CommitLoad` 复用同一资源链：StepLoad 先推进资源，随后在主线程按节点数量和时间预算恢复候选场景，ready 后 CommitLoad 切换所有权。GPU 准备仍由 RenderSystem 负责。资源完成数只描述依赖资源，不表示节点恢复或 GPU 首帧就绪，不能据此报告整个切换已经完成。完整契约见[资源加载接口](class-diagrams/resource-loader.md#加载阶段与限制)。

`Scene.Load` 和原生 `load()` 仍明确同步，适用于启动、工具和调用方选择的简单流程。当前 showcase 的场景入口仍使用 `Scene.Load`。异步加载由调用方组合 Begin/Step/Commit。配置异步任务域不会自动改变这些同步入口的语义；启动、脚本模块预检、存储工具及部署摘要也不能笼统视为已完全异步。

## 更新与发布边界

`update_catalog()` 校验完整候选及挂载，成功原子替换并进入新代际，失败保留旧目录和代际。旧 ResourcePtr 与完整依赖闭包继续拥有旧数据，不阻止合法目录发布；新 `load/find` 只使用当前代际，相同 GUID 的不同版本不会混用。

目录换代不使外部文件修改自动具备事务性。编辑器仍协调源导入、cache/gen 发布与项目启停；转换失败保留旧正式产物，只有完整候选才提交新目录。旧已加载闭包不重新读取被替换文件，新的加载按当前目录读取。

核心不隐式停止项目、不执行脚本回调、不自动恢复项目。目录代际只隔离已加载资源与缓存，不实现任意对象状态迁移。真机正常启动只提交一次清单；MCP 调试先准备完整候选内容到 App 持久可写目录，再由宿主显式应用，不能提前覆盖活跃包。

持久版本优先由宿主选择。核心只按本次明确提交的目录和挂载读取，缺失条目不得私自回退并复活已删除资源。

## 格式约束

资源目录使用版本 2，实体使用版本 1。仓库项目直接采用当前逻辑路径及配置，不提供旧前缀转换或旧项目配置兼容；导入器指纹变化后重新生成缓存。目录提交不逐个读取实体；完整部署校验由构建或同步调用方完成。

公开方法和所有权在[独立类图](../class-diagrams/index.md#资源系统)维护；场景、组件与脚本的资源引用关系见[领域使用者](class-diagrams/resource-system.md#领域使用者)。
